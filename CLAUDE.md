# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Project Truth Engine ingests a messy folder of project artifacts and reconstructs a
trustworthy, self-updating picture of a project (timeline, gaps, current-vs-drifted
direction). The product spec is [`PROJECTSPECS.md`](PROJECTSPECS.md); read it for the
"why". This repo is currently the **scaffold** — schema, API/auth skeleton, provider
adapters, and deploy tooling — with the processing pipeline still to be built on top.

## Commands

Local dev DB is exposed on host port **5433** (5432 is intentionally left free), so set the
URL when running tools against it:

```bash
export TRUTH_DATABASE_URL="postgresql+psycopg://steward:steward@localhost:5433/steward"

uv sync --extra dev                 # venv + core + dev deps (add --extra pipeline for ML/parsing)
docker compose up -d db             # Postgres + pgvector on localhost:5433
uv run alembic upgrade head         # apply schema (also CREATE EXTENSION vector)
uv run python -m truth_engine.db.seed   # idempotent phase-template seed
uv run uvicorn truth_engine.api.app:app --reload   # http://localhost:8000

uv run ruff check src alembic       # lint (must pass)
uv run pytest                       # tests
```

Changing the schema: edit `src/truth_engine/db/models.py`, then
`uv run alembic revision --autogenerate -m "msg"`. **Autogenerate needs hand-fixups**
(see Gotchas). Verify sync with `uv run alembic check` — it must say "No new upgrade
operations detected." Full private stack (app+db+ollama+caddy): `docker compose up -d`.

## Architecture

One Python package, `src/truth_engine/`, whose subpackages map 1:1 to the pipeline steps in
PROJECTSPECS.md §2:

| Package | Pipeline step(s) | Nature |
|---|---|---|
| `ingest` | 1 discover/hash/dedupe, stable IDs | deterministic |
| `parse` | 2 per-format extraction | deterministic |
| `extract` | 3 NER + confidence-scored dates + tables | deterministic |
| `store` | 4 persistence over `db.models` | deterministic |
| `embed` | 5 chunk + doc embeddings | local model |
| `analysis` | 6–10 timeline, phases, direction/drift, gaps | signals + **LLM judgment** |
| `reasoning` | provider adapters (LLM + embeddings) | — |
| `auth` | multi-user, owner-scoped isolation | — |
| `api` | FastAPI surface | — |

**The deterministic/LLM boundary is load-bearing:** steps 1–5 never send raw files to an
LLM. LLM reasoning (`reasoning.providers`) is used *only* for judgment inside analysis:
direction/drift labels, gap detection, renaming, report synthesis. Keep it that way — it's
what makes the system auditable and cheap.

**One store:** PostgreSQL + pgvector holds structured data, the relationship graph,
audit/versioning, *and* embeddings (`db.models.Embedding.vector`). No separate vector DB.

## Schema invariants (don't break these)

- **Identity is `Artifact.id` (UUID) + `content_hash`, never filename/path.** Re-ingesting a
  moved file must match on hash.
- **Multi-tenant:** everything is reachable to a `users` row via `project_id`/`owner_id`.
  Every query in a request path must be owner-scoped (use `auth.users.current_active_user`).
- **Auditability:** any inferred fact (date/entity/phase/label/gap/rename) writes a
  `DecisionAudit` row (actor, model, old/new value, rationale).
- **Reversibility / non-destructive:** suggested names/structure live in `ViewProjection`
  (versioned); original files are never mutated or moved.
- **Incremental:** `StageState(artifact_id, stage, input_hash)` gates reprocessing — skip a
  stage when `input_hash` is unchanged.
- **Config-driven phase models:** add a vertical by adding rows to `PhaseTemplate`
  (see `db/seed.py`), not by writing code.
- `EMBEDDING_DIM` in `db/models.py` **must** match `Settings.embedding_dim` and the chosen
  embedding model, and matches the `Vector(...)` column in the migration.

## Conventions

- Config via `truth_engine.config.Settings` (env prefix `TRUTH_`, `.env` file). Never read
  `os.environ` directly.
- Model access goes through `reasoning.providers` adapters. Default is fully private
  (local Ollama LLM + local sentence-transformers). Opt into a hosted model only via
  `TRUTH_LLM_PROVIDER=anthropic` (+ key) — it trades privacy for quality; keep it opt-in.
- DB enums are `enum.StrEnum` stored as `Enum(..., native_enum=False)` (VARCHAR + CHECK),
  for painless migrations.
- Heavy ML/parsing deps live in the `pipeline` optional group so the API and migrations
  boot without them; import them lazily inside the modules that need them (see
  `LocalEmbeddingProvider`).

## Gotchas

- **Autogenerated migrations need three hand-fixups** (Alembic can't infer them): add
  `import pgvector.sqlalchemy` and `import fastapi_users_db_sqlalchemy` at the top, and
  prepend `op.execute("CREATE EXTENSION IF NOT EXISTS vector")` as the first line of
  `upgrade()`. The existing initial migration shows the pattern.
- Alembic uses a **sync** psycopg engine (`alembic/env.py`); the app uses the **async**
  engine (`db/session.py`). Same `TRUTH_DATABASE_URL` works for both (psycopg 3).
